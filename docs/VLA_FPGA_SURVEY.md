## 0. 摘要

本文分三部分。

**第一部分：梳理 VLA 模型的计算特征与部署现状。** VLA（Vision-Language-Action，视觉-语言-动作）模型可以分三类：

- 以 RT-2 [1]、OpenVLA [2] 为代表的“离散动作 token 自回归”；
- 以 Octo [3]、GR00T N1 [7] 为代表的“扩散动作头”；
- 以 π0 [4]、π0.5 [5]、SmolVLA [8] 为代表的“流匹配（flow matching）动作专家”。

后两类的推理负载由两部分组成：一段形状接近大语言模型 prefill（预填充）的视觉-语言前缀，外加一个被迭代 5～10 次的小型 Transformer。前者的 GEMM 行数 M 为数百，属于算力受限；后者 M 只有几十，属于权重搬运受限。这种“双形态负载”与纯 LLM 解码（M=1、极端带宽受限）的差异，是 FPGA 部署 VLA 的核心难点。它也决定了照搬 FlightLLM [22]、DFX [23] 一类 LLM 解码加速器的设计并不够用。

**第二部分：对照已发表的 FPGA 上的 Transformer / LLM 工作。**

- FlightLLM [22]、DFX [23]、HLSTransform [24]、Chen 等的空间加速分析 [25]；
- Allo [26] / HeteroFlow [27] 类编译栈；
- SpAtten [28] 等注意力加速器；
- Versal AIE 上的 CHARM [29] 与 SSR [30]；
- MSFP [33] / MX [32] 块浮点格式。

对比按五个维度展开：数据流/阵列组织、量化、片上存储与片外带宽、编译与调度、实测平台与指标。检索范围内，本文**没有找到**已发表的、把完整 VLA（VLM 前缀 + 动作头）跑在单片 FPGA 上的工作。最接近的是 Corki [39] 这类机器人计算流水线协同设计、面向扩散策略的端侧优化 [40]、机器人学习用的 MX 精度可伸缩硬件 [41]，以及跨加速器的 VLA 表征研究 [17][18]。

**第三部分：解析本项目。** 本项目在 Achronix Speedster7t AC7t1500 上端到端运行 π0 的整块动作推理（一个 chunk）：

- 在 W8A8 精度下，实测 1.221 s/chunk [M]；
- 46 帧上关节角最大误差 0.665°、平均 0.072° [M]；
- 结果与编译器期望内存逐拍一致（bit-exact）[M]。

同一模型在 Jetson AGX Thor 上 bf16 编译的时延为 125.3 ms [M]，二者相差约 9.7 倍 [派生：1.221 / 0.1253 ≈ 9.74]。关于这个倍数有两点需要说明：

- 简报第 6 节写的是“约 8 倍”。按简报自身数字，8 倍对应的是 INT4 设计点（1.007 / 0.1253 ≈ 8.04 [派生]），而该点精度不可用（关节最大误差 44.9° [M]）。本文按“匹配精度”口径采用 9.7 倍，并在此指出这处不一致。
- Thor 的 125.3 ms 为 bf16，简报没有给出 Thor 端相对 fp32 的误差。因此“匹配精度”只是近似说法。

本文的判断如下：

- **创新性。** 本项目的主要创新在系统与编译层面：35 个自主节点靠 GDDR6 标志字同步；列并行 MLP72 级联链让每级乘法器满负荷；结果通路 epilogue（尾处理）上板；整个 chunk 可逐拍核对。
- **主要短板。** 短板在向量（非线性）通路和串行权重装载。按简报的校准模型，二者合计约占 65% [P]。另一个结构性约束是布线资源：MLP72 的使用率仅约三分之一。
- **后续方向。** 最有希望的方向依次是：向量通路的结构性扩容与算子融合；把前缀 KV 和动作专家的部分权重驻留片上；BFP8 上板；减少流匹配步数一类算法手段。算法手段需要与模型方共同验证。

## 1. 背景：VLA 模型族谱与计算特征

### 1.1 模型族谱

VLA 模型是在预训练的视觉-语言模型（VLM，Vision-Language Model）之上，增加从“观测 + 指令”到“机器人低层动作”映射能力的一类策略模型。从部署角度看，决定计算形态的首先是**动作的表示与生成方式**，其次才是骨干网络的规模。按动作生成方式，可以把主流工作分成三支。

**第一支：离散动作 token 的自回归生成。** RT-2 [1] 把机器人动作离散化为文本 token，与互联网规模的视觉问答数据共同微调 VLM。推理时，动作像文字一样逐 token 解码。OpenVLA [2] 沿用这一路线，组成如下：

- 语言骨干为 Llama 2；
- 视觉编码器融合 DINOv2 与 SigLIP 特征；
- 规模为 7B 参数；
- 在约 97 万条真实机器人示教上训练。

π0-FAST 所用的 FAST 分词器 [6] 用离散余弦变换压缩动作序列，缓解了逐维逐步分箱在高频控制下表现差的问题。它仍属于自回归生成，但每个动作块所需的 token 数显著减少。

这一支的推理形态与 LLM 几乎相同：一次前缀 prefill，接若干步 M=1 的解码。因此它能直接继承 LLM 推理栈的全部优化，也继承了 LLM 解码的带宽瓶颈。OpenVLA-OFT [13] 改用并行解码、动作分块、连续动作表示和 L1 回归目标，把这一支推向“单次前向输出整块动作”。据其摘要，动作生成吞吐提升约 26 倍。这个结果说明：逐 token 自回归并不是动作生成的必需形态。

**第二支：扩散动作头。** Diffusion Policy [11] 把视觉运动策略表示为动作空间中的条件去噪扩散过程，并引入滚动时域（receding horizon）执行。Octo [3] 是基于 Transformer 的通用策略，用扩散解码输出动作，在 Open X-Embodiment 的约 80 万条轨迹上预训练。它有 27M 与 93M 两个规模，远小于 VLM 类模型。GR00T N1 [7] 采用“双系统”结构：VLM 模块（System 2）负责理解，扩散 Transformer（DiT）模块（System 1）负责生成连续动作，二者端到端联合训练；公开的检查点规模为 2B。

**第三支：流匹配动作专家。** 流匹配 [12] 通过回归固定条件概率路径上的向量场来训练连续归一化流。与扩散相比，它训练更稳定，推理可以用少量 ODE 积分步完成。π0 [4] 在 PaliGemma VLM [9] 上增加一个独立参数的“动作专家”，以流匹配方式生成连续动作块。π0.5 [5] 在 π0 基础上引入异构数据协同训练，报告了在未见过的家庭环境中执行 10～15 分钟长程任务的能力。SmolVLA [8] 把整套方案压缩到约 4.5 亿参数，面向消费级 GPU 乃至 CPU 部署。

本项目部署的 π0 属于第三支。按简报，其结构为：

- **视觉编码器：** SigLIP So400m/14，27 层，宽 1152，16 头 × 72。
- **语言模型：** Gemma-2B，18 层，宽 2048，MLP 宽 16384，采用 GeGLU；8 个查询头 × 256，共享 1 个 KV 头。
- **动作专家：** 约 3 亿参数，18 层，宽 1024，MLP 4096；关注 VLM 的 KV cache（键值缓存）。
- **每次推理：** 10 个 Euler 积分步，输出 50 个未来动作。

检查点在 DROID 数据集 [10] 上微调。该数据集用 Franka Panda 7 自由度机械臂采集，共约 7.6 万条轨迹。

### 1.2 VLM 前缀与动作头：算子与访存特征

**一个 chunk 的计算构成。** 按简报，π0 在本项目的部署形态下，一次推理（下称“一个 chunk”）包括三段：

1. 两路相机图像经 SigLIP 编码为 2 × 256 个视觉 token；
2. 视觉 token 与语言 token 组成 525 个 token 的前缀，经 Gemma-2B 做一次前缀计算，生成 KV cache；
3. 动作专家对 51 个 token（1 个状态 + 50 个动作）迭代 10 步，每步关注 525 个前缀键和自身的键。

简报给出每个 chunk 约 1.47 TMAC [P]。为了让读者能核对这个量级，本文按简报的结构参数做了一个粗略的自检 [估算]：

- **Gemma-2B 前缀。** 每层线性层权重约为
  $2048\times2048\times2 + 2048\times256\times2 + 3\times2048\times16384 \approx 1.10\times10^8$。
  18 层合计约 $1.98\times10^9$，乘以 525 个 token，约 1.04 TMAC。
- **SigLIP。** 每层约 $4\times1152^2 + 2\times1152\times4304 \approx 1.5\times10^7$（MLP 宽度 4304 为 So400m 的公开配置，本文未从简报读到，属估算输入）。27 层、512 个 token，约 0.21 TMAC。
- **动作专家。** 每层约 $1024\times2048\times2 + 1024\times256\times2 + 3\times1024\times4096 \approx 1.73\times10^7$。18 层、51 个 token、10 步，约 0.16 TMAC。
- **注意力矩阵乘。** 为数十 GMAC 量级。

合计约 1.4～1.5 TMAC，与简报的 1.47 TMAC [P] 一致。这个估算的意义不在数字本身，而在比例：前缀计算（SigLIP + Gemma-2B）约占 85%，动作专家约占 11%，其余为注意力。

**算术强度决定了两类 GEMM 的瓶颈。** 用 roofline（屋顶线模型）的语言，一个 $M\times K$ 激活乘 $K\times N$ 权重的 GEMM，其算术强度为

$$
I=\frac{2MNK}{NK\,b_w+(MK+MN)\,b_a}\;\xrightarrow{\;M\ll N,K\;}\;\frac{2M}{b_w}\quad(\text{ops/byte}),
$$

其中 $b_w$、$b_a$ 分别是权重和激活的字节宽度。这里的关键是：当权重不能驻留片上、每次都要从片外读取时，强度只由行数 M 决定。在 INT8 权重下：

- **前缀 GEMM（M≈525）：** 强度上限约 1050 ops/byte。只要片上缓冲能容纳足够大的权重分块并充分复用，它是算力受限的。简报的表述是“activation re-streaming dominates”：激活的反复重读占主导，瓶颈转为片上缓冲容量与激活重流。
- **动作专家 GEMM（M=51）：** 强度只有约 102 ops/byte，而且每个积分步都要把全部专家权重再走一遍。简报称之为“weight-movement-bound”（权重搬运受限）。
- **LLM 自回归解码（M=1）：** 强度约 2 ops/byte，是 FlightLLM [22]、DFX [23]、EdgeLLM [31] 等工作的主要对象。

所以，VLA 的动作头处在 prefill 与 decode 之间的“中间地带”：带宽敏感，但又不像解码那样可以简单地用“带宽 × 位宽”一个量来刻画。

**权重搬运量的量级。** 下面给出 INT8 下每个 chunk 的最小片外权重流量 [估算]：

- VLM 前缀（SigLIP + Gemma-2B）线性层权重约 2.4 GB，每个 chunk 至少读 1 遍；
- 动作专家权重约 0.31 GB，若不能驻留片上，10 步共读 3.1 GB。

也就是说，**动作专家的计算量只占约 11%，其权重流量却超过总权重流量的一半**。这是流匹配 VLA 与纯 LLM 推理最显著的访存差异，也是后文讨论“专家权重驻留”和“步间权重复用”的出发点。

**KV cache 的量级。** Gemma-2B 只有 1 个 KV 头（头宽 256）。前缀 KV 的规模为 525 token × 18 层 × (K + V) × 256 元素，bf16 下约 9.7 MB，INT8 下约 4.8 MB [估算]。动作专家每个积分步都要在每一层重读这份 KV，10 步即重读 10 遍。对 FPGA 而言，这个量级处在“有可能驻留片上”的范围内。按简报，器件有 2,560 块 BRAM72K；若按名义容量每块 72 Kb 计算，合计约 23 MB [派生：2560 × 72 Kb ÷ 8]，与 KV 大小同量级。这是一个 LLM 长上下文解码中不存在的机会：VLA 的前缀短而固定，KV 被高频复用。

**非线性算子。** Transformer 中的非线性与归一化算子包括 LayerNorm / RMSNorm、softmax、GELU / GeGLU、RoPE、残差相加，以及量化方案带来的按 token 求尺度、反量化和再量化。这些算子的 MAC 数可以忽略，但有三个特点：

- 它们是逐元素或逐行归约的，访存与计算比接近 1；
- 它们需要浮点或高精度定点；
- 它们处在 GEMM 之间的关键路径上。

在 GPU 上，这类算子通过 kernel 融合和 FlashAttention [38] 一类的分块技术被藏进 GEMM 的访存阴影。在自研加速器上，如果向量通路的吞吐没有随矩阵阵列同比例扩展，它们就会按 Amdahl 定律成为主导项。简报的时延分解正是这一现象的直接证据：向量工作约占 50% [P]，INT4 之后约占关键路径的 82% [P]。这在第 3 节和第 4 节会详细讨论。

**迭代结构。** 流匹配的 10 个积分步之间存在严格的数据依赖：第 k+1 步的输入是第 k 步 Euler 更新后的动作。因此，**在单个 chunk 内，各步只能流水而不能并行**。能够并行或复用的是：

- 各步共享的前缀 KV；
- 各步完全相同的专家权重；
- 步内 51 个 token 之间的行并行。

这与扩散模型的多步去噪结构同构。它与 LLM 解码“每步只多一个 token”的形态也不同：流匹配每步重算全部 51 个 token。

### 1.3 机器人闭环对时延、抖动与功耗的要求

机器人策略运行在感知—推理—执行的闭环中，与离线的 LLM 服务相比，至少有三点根本差异。

**第一，时延直接进入控制回路。** 在动作分块（action chunking）执行下，策略一次输出未来 H 步动作（π0 在本项目中 H = 50），执行器按控制频率逐步执行。若推理时延 $T_{inf}$ 小于一个动作块的执行时长 $H/f_{ctrl}$，就可以在执行当前块的同时计算下一块，实现不停顿的连续控制。Real-Time Chunking（RTC）[14] 系统地讨论了这一问题：同步执行会在块边界产生停顿；朴素的异步执行又会在块边界产生分布外的跳变。RTC 的做法是在执行当前块时生成下一块，“冻结”必然会被执行的动作，对其余部分做 inpainting（补全）。该文报告 RTC 对推理延迟有较强的鲁棒性。这意味着：

- 在异步执行下，**推理时延决定的是“观测到动作”的反应滞后和块间一致性**，而不是能否运行；
- 可接受的时延上界与任务动态性强相关。对于点火柴一类高精度动态任务，时延越低越好。

以一个量纲关系说明约束的形式：若控制频率为 $f_{ctrl}$、执行视野为 $H_{exec}\le H$，异步执行要求

$$
T_{inf} + T_{io} \le \frac{H_{exec}}{f_{ctrl}},
$$

同时反应滞后约为 $T_{inf}+T_{io}$。其中 $T_{io}$ 包含相机采集、传输与主机调度。本项目简报给出主机开销约 47 ms/次调用；这个数字本身已占 Thor 端整个 chunk 时延（125.3 ms [M]）的约 38% [派生：47 / 125.3]。这提示：在百毫秒以内的目标区间，系统级开销与加速器内核同等重要。

**第二，抖动比平均时延更要紧。** 控制器按固定周期调度，一次偶发的长尾时延就可能导致动作队列耗尽、机械臂停顿，或迫使 RTC 类算法冻结更长的前缀。GPU 与 SoC 上的推理受动态频率调节、内存控制器仲裁、操作系统调度和共享缓存干扰的影响，尾延迟不易从结构上保证。确定性执行的加速器更容易给出最坏情况时延上界：Groq TSP [37] 去掉了仲裁器、缓存等“反应式”硬件；Brainwave [36] 则采用 batch-1 实时服务。静态调度的 FPGA 数据流设计同样有此属性。本项目编译器能够预先给出每次运行的期望内存，并逐拍核对，这是确定性的一种体现。但简报没有给出时延分布（方差或 P99），这一点在第 4 节作为缺口讨论。

**第三，功耗与散热受整机约束。** 移动机械臂或人形机器人的计算单元往往要和电机驱动、电池、散热共享预算。NVIDIA 公布 Jetson AGX Thor 的功耗区间为 40～130 W [21]，这一平台本身就是以“机器人整机可承受的功耗”为目标设计的。FPGA 方案若要在机器人上有意义，就必须同时给出每个 chunk 的能耗，而不仅是时延。本项目的简报没有给出功耗或能耗数字，因此本文不对本项目的能效做任何数值判断。

综合三点，VLA 部署的评价指标应当是一个向量：（平均时延、尾时延、每 chunk 能耗、动作精度、系统开销），而不是单一的吞吐或 TOPS/W。第 2 节的文献对比表之所以把“实测平台与指标”列为单独一栏，原因就在于此：大部分 FPGA 上的 LLM 工作报告的是 tokens/s 或能效比，与机器人闭环的指标并不直接对应。

## 2. 部署现状

### 2.1 GPU 与边缘 SoC 上的 VLA 推理优化

**平台。** 在机器人端侧部署大模型，目前的主流平台是 NVIDIA Jetson 系列。按 NVIDIA 官方页面与技术博客的公开信息 [21]，Jetson AGX Thor 的主要规格如下：

- Blackwell 架构 GPU，标称 2070 FP4 TFLOPS；
- 128 GB LPDDR5X 内存，带宽 273 GB/s；
- 模组功耗 40～130 W；
- 官方称其 AI 算力约为 AGX Orin 的 7.5 倍。

需要指出，标称的 FP4 峰值依赖特定的数据格式和稀疏性条件，与 bf16 下 VLA 的实际可达性能没有简单的换算关系。

**把 Thor 的实测结果放到屋顶线上看。** 本项目在 Thor 上的对照点是 bf16 编译的 π0，125.3 ms/chunk [M]。按 1.2 节的估算，bf16 下每个 chunk 的权重流量约为：VLM 前缀约 4.8 GB，加上专家 10 步约 6.2 GB（假设专家权重不能驻留在 GPU 的片上缓存中），合计约 11 GB。按 273 GB/s 计算，纯权重流量的带宽下界约 40 ms [估算]。实测 125.3 ms 大约是这个下界的 3 倍。这说明，即使在成熟的 GPU 软件栈上，π0 也远未达到带宽屋顶。其余时间可能来自：

- 前缀 GEMM 的算力项；
- 非线性算子；
- kernel 启动开销；
- 注意力的中间结果读写。

简报没有给出 Thor 端的时延分解，本文无法进一步定位。这个估算也提醒读者：“FPGA 比 Thor 慢 9.7 倍”不等于“FPGA 与带宽下界差 9.7 倍”。双方各自距离自己的屋顶都有空间。

**VLA 专用的推理优化。** 已发表的工作大致沿五条路线展开。

1. **改变动作生成的形态。** OpenVLA-OFT [13] 把自回归逐 token 解码换成并行解码 + 动作分块 + 连续回归头，吞吐提升约 26 倍。FAST [6] 通过压缩动作 token 缩短解码长度。这类方法改变的是负载本身，对任何硬件平台都有效。
2. **跨帧复用视觉计算。** VLA-Cache [15] 利用机器人操作中相邻帧的时间连续性，识别变化很小的视觉 token 并复用其 KV，只对与任务相关、对环境敏感的 token 重算。据摘要，它在 LIBERO、SIMPLER 和真实机器人上取得最高约 1.7 倍的 CUDA 时延加速，成功率损失可以忽略。这条路线对应本文 1.2 节的观察：前缀计算约占 85% 的 MAC。
3. **动态深度 / 早退。** DeeR-VLA [16] 采用多出口结构，按情境难度决定激活多少层。在 CALVIN 基准上，它报告计算量降低 5.2～6.5 倍、显存降低 2～6 倍。
4. **量化。** 2025～2026 年出现了一批专门针对 VLA 的后训练量化工作，包括 QuantVLA、DA-PTQ、HoloQ-VLA [20] 等。VLAQuantBench [19] 做了闭环评测，据摘要其结论包括：在 W4 权重下再把激活量化到 8 位，在四个“模型—任务”组合上使成功率下降 18～40 个百分点；并且 W4A4 下结果强烈依赖于哪些层被量化。这与本项目“INT4 在所有非注意力 GEMM 上不可用”的实测 [M] 在方向上一致：VLA 的动作输出对低比特误差的敏感度高于语言任务。需要注意，这些工作多以仿真基准的成功率为指标；本项目以相对 fp32 的关节角误差为指标，两者不能直接换算。
5. **系统级表征与异步执行。** VLA-Perf [17] 建立了 VLA 推理的解析性能模型。它系统讨论了模型规模、结构选择、长视频上下文、异步推理和双系统模型对时延的影响，以及端侧、边缘服务器、云端三种部署位置的取舍。另一项跨加速器表征工作 [18] 提出了“成本—能耗—时间”（CET）排行榜。它指出 VLA 推理存在两重串行性：VLM 与动作专家之间的流水线级串行，以及扩散过程内部的组件级串行。据此它提出两种免训练的加速方法。这两项工作的共同结论是：VLA 推理的瓶颈分布与 LLM 服务不同；“按实时约束选合适规模的边缘加速器”可能比旗舰 GPU 更具成本和能耗优势。

**端侧的扩散策略。** LightDP [40] 面向移动设备加速扩散策略，路线是压缩去噪网络并减少采样步数。它表明，“减少积分/去噪步数”是扩散和流匹配策略端侧部署的通用手段。

**小结。** GPU / SoC 路线的优化以算法和软件为主，硬件是给定的。它们的收益（26 倍、1.7 倍、5～6 倍等）大多与硬件平台正交，可以叠加到 FPGA 方案上。这也意味着，FPGA 方案与 Thor 的比较必须在同一算法版本（同样的步数、同样的 token 数、同样的量化）下进行，否则没有意义。本项目与 Thor 的对照满足这一点：同一个 π0 chunk，只是数值格式不同（W8A8 对 bf16）。

### 2.2 FPGA 上的 LLM / Transformer 代表工作

以下按“做了什么、怎么组织阵列、怎么量化、怎么处理存储、怎么编译调度、在什么平台上报告了什么指标”逐一梳理。数字取自各文献摘要级信息，均附编号。

**FlightLLM [22]（FPGA 2024）。** 面向 LLM 推理的完整映射流程，平台为 Xilinx Alveo U280。三项关键技术是：

- 可配置稀疏 DSP 链：用 DSP 级联支持多种稀疏模式；
- always-on-chip decode（解码阶段激活常驻片上）：配合混合精度以提升有效带宽；
- 长度自适应编译：降低不同序列长度下的编译开销。

据摘要，在 batch = 1 的 LLaMA2-7B 上，它相对 NVIDIA V100S（vLLM + SmoothQuant）取得 6.0 倍能效和 1.8 倍成本效率。FlightLLM 与本项目在思想上最接近：两者都利用硬核的级联（DSP 链 / MLP72 cascade）组织矩阵阵列，也都依赖完整的编译流程。区别有三：

- FlightLLM 的优化目标是 M=1 解码；
- 它利用 HBM 与稀疏性；
- 它不涉及多步迭代的动作头。

**DFX [23]（MICRO 2022）。** 这是由 4 块 Alveo U280 组成的多 FPGA 设备，端到端执行 GPT-2 的摘要（prefill）和生成（decode）两个阶段。设计要点为：

- 使用模型并行与“模型—硬件感知”的数据流；
- 计算核执行自定义指令；
- 用满 HBM 的所有通道；
- 板间以 QSFP 组成环网。

据摘要，它相对 4 块 V100 取得 5.58 倍加速和 3.99 倍能效。DFX 的启示在于“自定义指令 + 端到端执行全部算子”。它没有把非线性算子留给主机，这与本项目“主机只装载输入、启动阵列、读回结果”的做法一致。

**HLSTransform [24]（ICML 2024 Workshop，据 ML Anthology 记录）。** 它用高层次综合（HLS，High-Level Synthesis）在 Virtex UltraScale+ VU9P 上实现 Llama 2 推理。据摘要：

- 每 token 能耗相对 Xeon CPU 降低最多 12.75 倍，相对 RTX 3090 降低 8.25 倍；
- 速度约为 RTX 3090 的 0.53 倍。

它的意义在于展示 HLS 流程的可达性，以及“能效优于 GPU、绝对速度不及 GPU”这一在 FPGA LLM 工作中相当普遍的格局。本项目与 Thor 的比较也落在同一格局中；只是本项目目前还没有能耗数据来支撑“能效”一侧。

**Chen 等，FPGA 空间加速 LLM 的潜力分析 [25]（ACM TRETS）。** 该文讨论模型专用的空间（spatial）加速：为特定算子或层专门化硬件单元，单元之间以数据流直连，尽量减少片外访问。其核心贡献有两项：

- 一个预测空间加速器性能的解析模型；
- 一套可组合的 HLS kernel 库。

在 U280 上，据摘要：

- BERT 相对此前的 FPGA 加速器最高加速 13.4 倍；
- GPT 的 prefill 阶段相对 DFX 加速 2.2 倍；
- decode 阶段相对 A100 加速 1.9 倍、能效提高 5.7 倍。

这篇工作与本项目的对照点是：它讨论了空间（层间流水）与时间复用（单一阵列逐层执行）之间的取舍。本项目的 35 节点阵列是二者的混合：节点各自运行程序，按层内分块并行，层间靠标志字同步。

**Allo [26]（PLDI 2024）与 HeteroFlow [27]（FPGA 2022）。** 这两项是 Cornell 团队在“解耦的硬件定制”编程模型上的代表工作。

- HeteroFlow 构建于 HeteroCL 之上，用统一的 `.to()` 原语描述数据放置：主机与加速器之间、加速器内 kernel 之间、kernel 内部三个粒度。
- Allo 把计算、存储、通信、数据类型四类定制从算法描述中解耦为可组合的原语，并支持类型安全的模块组合。

这类编译栈解决的是“如何用高层描述生成高效的空间加速器”；本项目的 chunk 生成器解决的是“如何把一个固定模型的整次推理调度到一个固定的节点阵列上”。二者处于不同抽象层：前者生成硬件，后者生成程序。它们有一个共同关心的问题：数据放置与计算调度的协同优化。本项目中对应的是 GDDR6 地址条带化、权重装载提升到等待之前、双缓冲 feeder 等手段。

**SpAtten [28]（HPCA 2021）等注意力加速器。** SpAtten 通过级联的 token 剪枝与 head 剪枝减少注意力的计算和访存，并设计了高吞吐的 top-k 排序引擎。它还提出渐进量化：先取高位计算，置信度低时再取低位重算。据摘要，它把 DRAM 访问量平均降低 10.0 倍，并相对 A3 加速器加速 1.6 倍。这一类工作的着眼点是长序列注意力。对 π0 来说，前缀只有 525 个 token，注意力的 MAC 占比很低，因此它们的主要借鉴意义不在注意力本身。可借鉴的是“对视觉 token 做运行时剪枝”这一思想：它与 VLA-Cache [15] 的出发点相通。

**Versal AI Engine 上的工作：CHARM [29]（FPGA 2023）与 SSR [30]（FPGA 2024）。**

- CHARM 观察到：把 BERT 中尺寸较小的矩阵乘层放在 Versal ACAP 上一个庞大的单体矩阵乘加速器上执行时，只能达到理论峰值的不到 5%。因此它提出组合多个异构的矩阵乘加速器，让它们并发服务不同尺寸的层。该文给出的平台背景是 400 个 AIE、1 GHz、fp32 峰值约 6.4 TFLOPs。
- SSR 进一步在 VCK190 上把空间并行与顺序执行混合，给出时延—吞吐的帕累托前沿。

这两项工作对本项目最直接的意义是：**“不同形状的 GEMM 需要不同形状的阵列”**。CHARM 的 5% 与本项目“前缀 M≈525 与专家 M=51 共享同一阵列”面对的是同一个问题。本项目的回应是运行时融合链对与链分裂（fission）两项技术。按简报，链分裂在运行时切换，只比最佳固定形状快 0.02～0.12% [P]。这说明在本项目的阵列粒度下，形状失配并不是主要矛盾。第 4 节会讨论这一结论的含义。

**EdgeLLM [31]。** 这是一个 CPU-FPGA 异构的边缘 LLM 加速器，平台为带 HBM 的 VCU128。它采用混合精度处理单元阵列与分组脉动结构：注意力用 FP16×FP16，前馈网络用 FP16×INT4；同时用统一的数据形状让不同算子无需数据重排。该文所在期刊为 IEEE TCAS-I（据检索结果，出版年份未能核实）。它是“按层类型分配精度”的一个代表，与本项目的“W8A8 全覆盖、INT4 全覆盖”两种均匀方案形成对照。

**硬核矩阵单元的实测对比：Stratix 10 NX [35]（FPT 2020）。** 该文首次在大量实时推理负载上对比了带 AI 张量块的 Stratix 10 NX 与 NVIDIA T4/V100。据摘要：

- 张量块的 INT8 峰值约 143 TOPS；
- 实际可达性能主要取决于张量单元的利用率和与主机之间的数据传输开销；
- 相对常规 DSP 的 FPGA 平均提升 3.5 倍。

这篇工作的结论与本项目的经验高度一致：硬核阵列的峰值不是瓶颈，利用率和系统开销才是。

**块浮点与 MX 格式。**

- MSFP [33]（NeurIPS 2020）是微软在 Brainwave [36] 生产系统中使用的一类块浮点格式：一组元素共享指数，元素本身用窄位宽尾数。据摘要，它在不修改模型拓扑的前提下，以低于 bf16 约 3 倍、低于 INT8 约 4 倍的成本达到相当精度，精度影响小于 1%。
- MX [32] 是在此基础上形成的开放规范。它定义块大小、共享尺度与窄位宽元素三要素，给出 MXFP8、MXFP6、MXFP4、MXINT8 四种具体格式；其报告称在二十余个基准上可作为 FP32 的直接替代，并首次在亚 8 位权重/激活/梯度下训练生成式语言模型。
- 面向机器人学习，已有工作 [41] 设计了支持 MX 的精度可伸缩硬件。

本项目的 BFP8 MLP72 链（BFP8 操作数、fp24 累加）属于这一谱系。简报显示，它在软件模拟中的动作误差为 0.70%，优于 INT8 的 0.97% [M, software]。这是块浮点“以接近 INT8 的硬件成本换取更好精度”这一论点在 VLA 上的一个具体数据点。

**量化方法。** SmoothQuant [34]（ICML 2023）通过数学等价变换，把激活中的离群值“迁移”到权重，从而使 LLM 的 W8A8 量化免训练且几乎无损；据摘要，它带来最高 1.56 倍加速和 2 倍内存节省。本项目在语言模型部分采用了 SmoothQuant，再加上按输出通道的权重量化（MSE 截断）和按 token 的动态激活量化。这是当前 W8A8 的标准配方。

**系统先例：Brainwave [36] 与 Groq TSP [37]。**

- Brainwave 在数据中心规模上以 FPGA 软处理器做 batch-1 的实时 DNN 服务。据 IEEE Micro 版本的摘要，它在 Stratix 10 上达到约 39.5 TFLOPs 的 batch-1 有效性能。
- Groq TSP 用功能切片的微架构与生产者—消费者流式编程模型，去掉仲裁器和缓存等反应式硬件，从而保证执行的确定性。

两者分别代表了“实时、无批处理”和“确定性”这两个机器人闭环同样关心的属性。

### 2.3 VLA 或机器人策略在 FPGA / ASIC 上的已发表工作

本文围绕“VLA + FPGA”“扩散策略 + FPGA”“机器人策略 + 加速器”做了多轮检索。截至撰写时，**没有检索到已发表的、在单片 FPGA 上端到端运行完整 VLA（VLM 前缀 + 动作头）的工作**。这里需要说明：“未检索到”受检索手段所限（见第 7 节核实说明），不等于“不存在”。与之最接近的工作有以下几类。

- **Dadu-Corki [39]（ISCA 2025；其预印本早期版本题为 Corki）。** 这是一个面向具身智能机械臂操作的算法—体系结构协同设计。它把 LLM 推理、机器人控制和数据通信在计算流水线中解耦：算法上让模型预测近未来的轨迹而非单帧动作，以降低大模型推理频率；硬件上加速从轨迹到关节力矩的转换，并让通信与计算并行。据检索摘要，它报告了最高约 3.6 倍的加速。它的着眼点是“降低大模型被调用的频率 + 加速控制端”，并不加速 VLM 本身。
- **跨加速器的 VLA 表征 [18]。** 该文在多种“XPU”上测量 VLA 推理，提出了免训练的加速方法。它研究的是既有加速器的选型与软件优化，而不是新硬件。
- **机器人学习中的 MX 精度可伸缩硬件 [41]。** 它面向的是机器人学习（含训练）的数值格式支持，是数值层面的硬件工作。
- **扩散策略的端侧部署 [40]。** 在移动 SoC 上压缩扩散策略，属于软件与模型层面。

因此，就“把一个数十亿参数的 VLA 完整映射到单片 FPGA、并以相对 fp32 的动作误差验证”而言，本项目在可检索的公开文献中处于空白位置。这既是它的新颖性所在，也意味着它缺少可以直接对标的学术基线；与 Thor 的对比是目前唯一的外部参照。

## 3. 方法论分析

### 3.1 为什么 VLA 比纯 LLM 解码更难上 FPGA

把 LLM 解码映射到 FPGA，问题可以大致归结为一个“带宽—位宽”的优化：每生成一个 token 都要把全部权重读一遍，因此时延下界约等于“权重字节数 ÷ 有效带宽”。FlightLLM [22] 和 EdgeLLM [31] 的设计几乎都围绕这一点展开：压缩权重、提高 HBM 利用率、让激活常驻片上。VLA 则至少在五个方面偏离了这一简化。

**（1）两类形状迥异的负载共享同一硬件。** 一个 chunk 内：

- 前缀 GEMM 的 M≈525，是算力受限或片上缓冲受限的；
- 动作专家 GEMM 的 M=51，是权重搬运受限的。

两类负载的 MAC 比约为 85：11，但权重流量比反而接近 1：1.3（1.2 节 [估算]）。

对固定的阵列而言：

- 为前缀优化的大阵列在专家阶段会因为 M 太小而闲置，行周期被 K 方向的权重装载主导；
- 为专家优化的小阵列在前缀阶段又会算力不足。

CHARM [29] 在 BERT 小层上观察到的不到 5% 的利用率，正是这种失配的极端情形。

本项目的阵列组织对此有一个专门的回应：列并行链的行周期是 $\max(W+1,\,d,\,\sim14)$ 个阵列周期（简报），其中 W 是一次行传递的激活字数，d 是链深（乘法级数）。当 M 较小时，一条链装载一次列权重后只能被 M 行复用，装载成本摊不开。简报把“串行权重装载”单列为约 15% 的时间 [P]，这正是 M=51 这一形状在硬件上的投影。

**（2）流匹配的多步迭代。** 10 个 Euler 步之间有严格的数据依赖，每步都要重算 51 个 token 的全部 18 层。这带来三个后果：

- 专家权重每个 chunk 要被完整读 10 次，除非能驻留片上；
- 各步不能像批处理那样并行，只能在层间和步间做流水；
- 每步都包含一整套非线性算子（归一化、激活、RoPE、softmax），它们的次数随步数线性增长。

对 LLM 解码来说，“步”是 token 维度的，每步只增加 1 行；对流匹配来说，“步”是时间积分维度的，每步都是完整的 51 行前向。两者在访存与计算比上的形态并不相同。

**（3）KV 的复用模式不同。** 在 LLM 解码中，KV cache 随序列增长，每个新 token 读一遍全部历史 KV；优化手段是分页、压缩、剪枝。在 π0 中，前缀 KV 是固定的 525 个 token，被 10 步 × 18 层反复读取；专家自己的 51 个 token 的 KV 每步重算。因此：

- LLM 长上下文的 KV 优化（如 SpAtten [28] 的剪枝）在这里收益有限；
- 反过来，“前缀 KV 驻留片上”在这里是可行的：bf16 约 9.7 MB，INT8 约 4.8 MB [估算]，而 BRAM72K 的名义总容量约 23 MB [派生]。这在 LLM 场景中通常不成立。

**（4）非线性算子的占比。** 如 1.2 节所述，非线性与量化相关的逐元素运算几乎不贡献 MAC，却处在关键路径上。在 W8A8 方案中还要叠加量化带来的额外工作：每个 GEMM 前要按 token 求尺度并量化，之后要按“行尺度 × 列尺度”反量化。本项目的简报给出了直接证据：

- 1.221 s 中约 50% 是向量工作 [P]；
- 把 GEMM 换成 INT4 之后，约 82% 的关键路径是向量工作 [P]。

这就是一个典型的 Amdahl 结构：矩阵阵列的任何加速，都会被未同步扩展的向量通路抵消。LLM 解码中这一问题相对不突出，因为 M=1 时 GEMM 本身已被带宽限死，向量工作的相对占比较低。

需要注意一个口径问题：简报的两个 [P] 占比分别指“1.221 s 的时间构成”和“INT4 设计点的关键路径占比”。二者口径不同，时钟也不同（向量域 288.9 MHz 对 279.6 MHz），本文不把它们相乘换算成绝对时间。

**（5）精度敏感性。** LLM 的量化通常以困惑度或下游任务准确率为指标。VLA 的输出是连续的动作轨迹：误差会沿动作块内的时间累积，并通过闭环放大。本项目的实测给出了一个很强的证据：在所有非注意力 GEMM 上采用 W4A4 之后，关节最大误差从 0.665° 增加到 44.9° [M]，简报的评价是“不可用”。VLAQuantBench [19] 等工作也观察到，W4 与 A4/A8 的组合对成功率有大幅影响，且强依赖于量化了哪些层。这意味着，FPGA 上常用的“低比特换吞吐”手段在 VLA 上的空间比在 LLM 上小，必须以逐层敏感度分析为前提。块浮点 [32][33] 是缓解手段之一：本项目软件模拟中 BFP8 的动作误差为 0.70%，优于 INT8 的 0.97% [M, software]。

### 3.2 FPGA 的机会

尽管有上述难点，FPGA 在 VLA 部署上仍有一些 GPU / SoC 不具备的结构性机会。

**硬核级联。** 现代 FPGA 的硬核矩阵单元之间有专用的级联通路：Achronix 的 MLP72 cascade、Xilinx 的 DSP 级联、Stratix 10 NX 的张量块链。级联把操作数或部分和在相邻硬核之间传递，不占用通用布线。FlightLLM 的稀疏 DSP 链 [22] 与本项目的列并行 MLP72 链都利用了这一点。

本项目的做法有其特殊之处。常见做法是“部分和沿级联向上累加”，这样每级只用到一个乘法器输出。本项目则把**同一个激活字**沿级联广播，每一级用自己 BRAM72K 中的一列权重与之相乘，并各自累加自己的列和。按简报的说法，这使每一级的 16 个（INT4 下 32 个）乘法器在一次行传递中全部忙碌；而“部分和沿级联相加”的替代方案会浪费其中的 15/16。这是一个针对 MLP72 微结构的数据流选择，第 4 节会进一步讨论它的代价。

**片上网络（NoC）与外存。**

- Speedster7t 的 2D NoC 把 GDDR6 控制器、PCIe 等接口连到 80 多个 fabric 接入点。据厂商资料 [42]，NoC 总带宽超过 20 Tbps；器件支持最多 32 GB 的外接 GDDR6。
- 本项目的 35 个节点各自拥有一个 NAP（NoC 接入点），直接从 GDDR6 读取程序、权重和激活，并通过 GDDR6 中的标志字同步。
- 这种“节点即 NoC 端点”的组织，避免了在 fabric 中布一张大型交叉开关。其代价是：节点之间所有通信都要经过 GDDR6 往返。

与之相对，DFX [23] 和 FlightLLM [22] 所用的 U280 依赖 HBM 与传统 AXI 互连。Versal [29][30] 则在 AIE 阵列与可编程逻辑之间有专门的数据通路。

**确定性时延。** 静态调度的 FPGA 数据流没有缓存未命中、没有操作系统抢占、没有动态频率调节，时延只取决于程序与数据布局。本项目的编译器能生成每次运行的“期望内存”，并在硅片上逐拍核对（bit-exact）。这是一种比“时延可预测”更强的属性：结果本身也可预测。对需要功能安全认证的机器人，这一属性的价值可能超过单纯的速度。

但需要强调两点：

- 片外 GDDR6 的刷新与 NoC 仲裁仍会带来少量不确定性；
- 简报没有给出多次运行的时延分布，因此“确定性时延”目前还是结构上的推论，不是测量结论。

**自定义数值格式。** FPGA 可以原生支持非标准格式：块浮点、按行/列尺度的混合精度、表查找的超越函数。MLP72 本身就支持块浮点模式。在 VLA 对精度敏感的前提下，这是 GPU 固定格式所不具备的调节维度。

**功耗与形态。** FPGA 板卡可以做到 PCIe 卡或更小的形态，功耗也可按设计裁剪。但本项目目前没有能耗数据，本文不对此做数值判断。

### 3.3 一个简化的时延模型

为了把后面的讨论放在统一的框架里，定义每个 chunk 的时延为

$$
T_{chunk} = T_{host} + T_{vis} + T_{pre} + S\cdot T_{step},
$$

其中：

- $T_{host}$ 为主机调度与数据交换；
- $T_{vis}$ 为 SigLIP 编码；
- $T_{pre}$ 为 Gemma-2B 前缀；
- $S$ 为积分步数（π0 中 S = 10）；
- $T_{step}$ 为动作专家单步。

每一项又可写成矩阵、向量、权重装载三部分在不完全重叠下的组合：

$$
T_{x} \approx \max\!\Big(\frac{\mathrm{MAC}_x}{P_{arr}\,\eta_{arr}},\;\frac{B^{w}_x}{BW_{eff}}\Big) + T^{vec}_x + T^{stall}_x,
$$

其中：

- $P_{arr}$ 为阵列峰值 MAC 率，$\eta_{arr}$ 为其利用率；
- $B^{w}_x$ 为该段的权重流量，$BW_{eff}$ 为有效外存带宽；
- $T^{vec}_x$ 是没有被 GEMM 遮盖的向量工作；
- $T^{stall}_x$ 是 feeder 等待与同步开销。

这个模型把优化手段自然地分为四类：

- 提高 $P_{arr}\eta_{arr}$（阵列更大、利用率更高、更低位宽）；
- 降低 $B^w$ 或提高 $BW_{eff}$（权重驻留、压缩、条带化）；
- 缩短 $T^{vec}$（向量通路扩容、融合、把非线性移入链的 epilogue）；
- 减小 $S$ 或 token 数（算法手段）。

对本项目，简报给出的 1.221 s 构成 [P] 可以直接代入：

- 向量工作 50%，即 $T^{vec}$ 总和约 0.61 s；
- 链计算 25%，约 0.31 s；
- 串行权重装载 15%，约 0.18 s；
- feeder 停顿 6%，约 0.07 s。

以上时间均为 [派生：1.221 s × 各占比]。

阵列利用率可以做一个上界估计 [派生]：

- 等效 MAC 率：1.47 TMAC / 1.221 s ≈ 1.20 TMAC/s。
- 全器件峰值：若按 2,560 个 MLP72 × 16 INT8 MAC/周期 × 500 MHz 计，约 20.5 TMAC/s（厂商按 750 MHz 标称的全器件 INT8 峰值为 61.4 TOPS [42]，即约 30.7 TMAC/s）。
- 以 500 MHz 为基准，等效利用率约 6%。
- 若只计简报所说实际使用的约 760～860 个 MLP72，其峰值上界约 6.1～6.9 TMAC/s，等效利用率约 17～20%。这里包含 feeder 等非乘法级，所以实际乘法级的利用率会更高一些。

作为对照，Thor 端 125.3 ms 对应约 11.7 TMAC/s 的等效率 [派生：1.47 TMAC / 0.1253 s]。

这组数字说明了差距的来源：**差距的主要来源不是“FPGA 的乘法器不够”，而是“乘法器之外的时间太多”和“能放下的乘法器太少”**。

## 4. 本项目解析（依据简报）

### 4.1 架构：节点阵列

本项目在一片 Achronix Speedster7t AC7t1500（VP815 PCIe 卡，PCIe Gen4 x16）上实现了 35 个自主节点，组成的“节点阵列”如下：

- 24 个整数 GEMM 链节点（12 个 32 级乘法、12 个 16 级乘法）；
- 3 个“PV”链节点，负责注意力的概率 × 值（uint8 × int8，16 级）；
- 8 个向量节点，每个 2 条 lane。

每个节点有自己的 NAP 接入 NoC，从 GDDR6 取自己的程序；节点之间以 GDDR6 中的标志字同步（WAIT / POST 命令）。主机只负责装载输入、启动阵列和读回结果。

**这个组织在体系结构上的含义有三点。**

1. **控制是分布式的。** 没有中央调度器。每个节点是一个按程序执行的小处理器，依赖关系在编译期展开成 WAIT / POST 对。这使阵列规模可以按节点扩展，而不需要扩展一个集中的控制通路。它的代价是同步延迟：每次同步都要经过 GDDR6 往返。
2. **存储层次是扁平的。** 节点间不直接互连（下文的融合链对是例外），所有中间结果都经 GDDR6 交换。这简化了布线，也把 GDDR6 带宽和访问时延暴露到了关键路径上。“feeder 停顿约 6%” [P] 和“向量工作的 int32 往返”都与这一点相关。
3. **矩阵与向量是分离的。** GEMM 链只做整数乘累加，归一化、softmax、激活、量化与反量化全部交给向量节点，以 bf16 为接口。这一分离让链保持简单、便于布线，但把向量通路变成了瓶颈。结果通路 epilogue 正是为了部分打破这一分离而引入的。

**列并行 MLP72 链。** 链的组织方式是：feeder MLP72 从自己的 BRAM 读出一个激活字，沿硬级联向上转发；每一级用自己 BRAM72K 中的一列输出权重与该字相乘，并累加自己的列和。按简报：

- 一次 W 个字的行传递产生 d 个输出列；
- 一个分块覆盖 $d\times\lfloor512/W\rfloor$ 列；
- 行周期为 $\max(W+1,\,d,\,\sim14)$ 个阵列周期。

从公式可以读出两件事：

- 当 W 较小（K 方向短）时，行周期被 d 或约 14 个周期的固定开销限制，乘法器会有空闲；
- 当 W 较大时，一个分块覆盖的列数减少，需要更多分块，权重装载次数随之增加。

这正是 M、K、N 三个维度与链深 d 之间的权衡。编译器按“深度类”对 GEMM 分块，目的就是在两类链（16 级与 32 级）之间做匹配。

**资源约束来自布线。** 简报明确指出，约束资源是 fabric 布线，而不是乘法器：

- 一个完整阵列只用了 2,560 个 MLP72 中的约 760～860 个，逻辑块占用率为 63～75%；
- 更大的阵列无法完成布线。

这一点对理解本项目的上限至关重要：可用乘法器只有约三分之一在工作，而且进一步扩大阵列的路径被布线堵住了。**fabric-light 链**就是针对这一约束的结构性改进：

- 权重通过 BRAM72K 的写级联装载，结果通过 MLP72 的输出级联分段引出；
- 每级只需约 2.4 个逻辑块，原方案为 21.2 个；
- 已在硅片上实现 912 个乘法 MLP72 [M]。

不过它目前的设计点时钟较低（310 / 216.7 / 177.3 MHz），整 chunk 为 1.588 s [M]，慢于最佳 INT8 设计点。这说明“能布下更多乘法器”尚未转化为“更快”：阵列时钟下降，而且向量通路没有同步扩展。

### 4.2 数值方案

**精确路径。** 每个 GEMM 都用 W8A8：

- 权重按输出通道量化（MSE 截断）；
- 激活按 token 动态量化为 INT8；
- 语言模型部分使用 SmoothQuant [34]；
- 注意力概率为 uint8；
- 所有向量接口为 bf16。

46 帧硅片实测的关节角最大误差 0.665°、平均 0.072°，相对 fp32 参考 [M]。

从文献角度看，这是一套稳健的标准配方。它的主要代价不在 GEMM 本身，而在两处：动态量化要在每个 GEMM 前逐 token 求尺度；反量化要在每个 GEMM 后按“行尺度 × 列尺度”恢复。二者都落在向量节点上。简报列出的“融合量化尾”和“按行 × 按列尺度的反量化”正是这部分工作。

**INT4。** 在所有非注意力 GEMM 上使用 MLP72 的 SIGNED 4×4 模式，整 chunk 为 1.007 s [M]，但关节最大误差为 44.9° [M]，不可用。简报的判断是“4 位权重对该模型是破坏性的”。

从方法论上，这个结果说明的是“均匀 W4A4 不可用”。它并不排除“逐层混合精度”或“W4 仅用于不敏感层”的可能性。EdgeLLM [31] 在 FFN 上用 INT4 权重、注意力保留 FP16，是一个可参考的混合方案。但任何这类方案都必须以 VLA 的动作误差为准重新验证。另外，INT4 设计点的收益本身也有限：1.221 s → 1.007 s，时延只降低约 18% [派生：(1.221 − 1.007) / 1.221 ≈ 17.5%]。原因是向量工作并没有因此减少。

**BFP8。** 在 MLP72 的块浮点模式下，用 BFP8 操作数、fp24 累加。它在软件模拟中的动作误差为 0.70%，INT8 为 0.97% [M, software]；目前只有 RTL 仿真，未上板。这是本项目在数值上最有潜力的方向：

- 它可能在不增加乘法成本的前提下提高精度；
- 它还可能简化部分量化 / 反量化工作，因为块内共享指数，尺度处理可以在链内完成。

后一点需要实际设计来确认，本文不作定量推断。

### 4.3 编译器：chunk 生成器

编译器把整个 chunk 降低为每个节点的程序。简报列出的优化包括：

- 按深度类做 GEMM 分块；
- 条带化的 GDDR6 地址映射；
- 双缓冲的 feeder；
- 把权重装载提升到等待之前；
- 量化融合；
- 注意力行块与层间重叠；
- 剪除无用工作（最后一个前缀层只需要它的 K/V）；
- 按节点做负载均衡。

编译器的“期望内存”模型使每次硅片运行都能逐拍核对。

**调度的收益。** 在同一套 INT8 硬件上，仅靠调度就把时延从 1.901 s 降到 1.221 s [M]，约 1.56 倍 [派生：1.901 / 1.221]。简报列出的调度手段依次是：内存布局、排序与重叠、融合、死代码剪除，最后是时钟。第一次整阵列运行的时延为 6.48 s [M]，到最佳 INT8 点累计改善约 5.3 倍 [派生：6.48 / 1.221]；这其中也包含了时钟和硬件迭代的贡献。

与文献对照：

- FlightLLM [22] 的“长度自适应编译”与 Chen 等 [25] 的解析模型，解决的是“为给定模型选出最佳硬件与映射”；
- Allo [26] 和 HeteroFlow [27] 解决的是“用高层原语生成硬件”；
- 本项目的 chunk 生成器更接近 DFX [23] 的“自定义指令 + 编译器”路线，但粒度更细：35 个节点各有程序，同步在编译期展开。

它最独特的一点是**可逐拍核对**：编译器同时是一个精确的功能模型。在文献中，这一属性通常出现在验证流程中，很少作为部署系统的一部分被强调。它的工程价值在于，每一次调度优化都可以在硅片上立即确认结果不变，从而放心地进行激进的重排和融合。

### 4.4 实测结果与时延构成

表 3 汇总简报中的硅片结果。

| 设计点 | 时钟（阵列 / 向量 / fabric，MHz） | chunk 时延 | 精度（46 帧） | 说明 |
|---|---|---|---|---|
| 首次整阵列运行 | — | 6.48 s [M] | bit-exact | 起点 |
| INT8，最佳调度 | 500 / 288.9 / 216.7 | **1.221 s** [M] | 关节最大 0.665° [M] | 当前可用的最佳点 |
| INT4 链（所有非注意力 GEMM 为 W4A4） | 437.5 / 279.6 / 244.6 | 1.007 s [M] | 关节最大 44.9° [M] | 精度不可用 |
| INT4 + GeGLU/GELU 链 epilogue 对比 INT4，同一比特流 | 481.25 / 248.4 / 180.7 | 1.047 s 对 1.115 s（−6.1%）[M] | 与 INT4 相同 | epilogue 与向量算子逐位一致 |
| fabric-light 链（912 个乘法 MLP72） | 310 / 216.7 / 177.3 | 1.588 s [M] | bit-exact | 布线友好，时钟低 |
| 对照：Jetson AGX Thor，bf16 | — | 125.3 ms [M] | 简报未给出 | 同一 π0 chunk |

在时延构成上，按简报的校准模型 [P]，1.221 s 中：

- 向量工作约 50%；
- 链计算约 25%；
- 串行权重装载约 15%；
- feeder 停顿约 6%；
- 主机开销约 47 ms/次调用（简报未注明 [M] 或 [P]，本文照录）。

INT4 之后，关键路径的约 82% 是向量工作 [P]。

**对表 3 的几点解读。**

1. **epilogue 的收益与瓶颈判断一致。** 在同一比特流上，把 GeGLU / GELU 移到链的结果通路，时延降低 6.1% [M]；K-split 反量化 epilogue 在 RTL 仿真中使对应向量阶段减少 81%、整 chunk 减少 6.4% [M, sim]。两者的方向都是“把向量工作挪进链内”，收益都在个位数百分比。原因是每项 epilogue 只覆盖了向量工作中的一小部分算子。
2. **时钟在不同设计点之间变化很大。** 阵列域从 310 MHz 到 500 MHz 不等，向量域从 216.7 MHz 到 288.9 MHz 不等。跨设计点比较时延时，时钟与结构的贡献混在一起。例如 INT4 + epilogue 的比较使用同一比特流，结论是干净的；而 INT8 与 INT4 两个最佳点的时钟不同，差值不能全部归于位宽。
3. **运行时可重构的收益有限。** 融合链对在仿真中减少读流量 11～23% [M, sim]，但预计时延收益约为 0 [P]；链分裂的运行时切换只比最佳固定形状好 0.02～0.12% [P]。在当前瓶颈（向量与权重装载）之下，改进 GEMM 形状适配对总时延几乎没有影响。这与 3.3 节模型的判断一致。

### 4.5 逐项对照文献的定位

**创新点（相对第 2 节文献）。**

1. **整模型、单芯片、端到端。** 在可检索的公开文献中，本文没有找到把完整 VLA（SigLIP + Gemma-2B 前缀 + 流匹配动作专家的 10 步迭代）放在单片 FPGA 上、主机只负责输入输出的工作（2.3 节）。FlightLLM [22] 与 DFX [23] 是整模型 LLM 推理；本项目在此基础上处理了双形态负载与多步迭代。
2. **列并行 MLP72 链的数据流。** 常见的级联用法是部分和沿链累加；本项目改为激活沿链广播、每级独立累加一列，使每级全部乘法器忙碌。这是一个针对具体硬核微结构的数据流创新。它的代价是每级需要自己的权重存储与结果引出，这一代价体现为布线压力。fabric-light 链又进一步把权重装载与结果引出迁移到硬级联上，以减轻这一压力。
3. **自主节点 + 存储器标志同步。** 与 DFX [23] 的中央指令流、FlightLLM [22] 的单一加速器相比，本项目的 35 个节点各自取指、各自同步，控制完全分布。这在 FPGA LLM 文献中不常见，更接近多核或数据流处理器的组织。
4. **结果通路 epilogue。** 把反量化、GELU / GeGLU、K-split 部分和合并放入 GEMM 链的结果通路，并与向量算子逐位一致。GPU 上的 epilogue 融合是常规手段，但在 FPGA 硬核链的结果通路上实现、并做到逐位一致，是本项目的工程贡献。
5. **可逐拍核对的编译器。** 每次硅片运行都有精确的期望内存。这一属性让积极的调度优化（1.901 s → 1.221 s [M]）可以安全推进；在需要可认证行为的机器人场景中，它也有额外价值。

**差距。**

1. **与 Jetson Thor 的差距：约 9.7 倍（匹配精度口径）[派生]。** 按 3.3 节的派生量：
   - FPGA 端的等效 MAC 率约 1.20 TMAC/s，Thor 端约 11.7 TMAC/s；
   - FPGA 端约三分之二的时间花在乘法之外（向量 + 权重装载，约 65% [P]）。

   要追平 Thor，仅加速矩阵阵列是不够的。即使矩阵时间降为零，只要向量工作还有约 0.61 s [派生]，时延就不可能低于 0.61 s。
2. **与 LLM FPGA 文献在带宽利用上的差距。** FlightLLM [22] 与 DFX [23] 都围绕 HBM 做了“用满全部通道”的设计；本项目使用 GDDR6，简报没有给出实测有效带宽。串行权重装载约 15% [P] 与 feeder 停顿约 6% [P] 说明，外存访问仍有未被遮盖的部分。
3. **稀疏与混合精度未被利用。** FlightLLM 利用了稀疏 [22]，EdgeLLM 采用按层混合精度 [31]。本项目目前只有均匀 INT8 和均匀 INT4 两个极端，缺少中间的逐层精度分配。
4. **缺少能耗与时延分布数据。** 与 DFX、HLSTransform、SSR 等报告能效比的工作相比，本项目没有能耗测量，也没有给出多次运行的时延分布。因此无法在“能效”和“确定性”这两个 FPGA 的传统优势维度上与 Thor 比较。
5. **可用乘法器的比例低。** 2,560 个 MLP72 中约 760～860 个在使用 [M]。相比之下，Stratix 10 NX [35] 的研究强调张量单元利用率是决定性因素，CHARM [29] 也把利用率作为核心优化目标。本项目的利用率受布线而非调度所限，这一点在已发表的 FPGA LLM 工作中较少被直接报告。

### 4.6 优势、劣势与风险评估

**优势。**

- **完整性。** 整个 π0 chunk 在 FPGA 上端到端运行，精度可用（关节最大 0.665° [M]），且与编译器期望逐位一致 [M]。这证明了“单片 FPGA 承载数十亿参数 VLA”在功能上可行。
- **工程可控性。** 可逐拍核对的编译器提供了强大的回归手段；调度优化的 1.56 倍 [派生] 就是在这一手段的支撑下得到的。
- **瓶颈清晰。** 校准模型给出了分项构成，epilogue 的实测收益与模型预测方向一致。团队对“下一步该优化什么”有量化依据。
- **结构性探索储备。** fabric-light 链已上板，BFP8、融合链对、K-split epilogue 已在 RTL 仿真中验证。这些都是可以组合的构件。

**劣势。**

- **绝对性能。** 比 Thor 慢约 9.7 倍 [派生]，距离闭环实时控制通常要求的百毫秒量级（以 Thor 为参照）还差一个数量级。
- **向量通路。** 8 个向量节点、每个 2 条 lane，承担了约一半的时间 [P]；INT4 之后更是占到约 82% 的关键路径 [P]。矩阵与向量的算力配比明显失衡。
- **布线约束。** 约三分之一的 MLP72 在工作，阵列无法继续扩大；fabric-light 虽能布下更多乘法器，但时钟下降。
- **外存往返。** 节点间所有数据都经过 GDDR6，同步也经过 GDDR6。这在降低布线压力的同时，把外存时延放上了关键路径。

**风险。**

- **精度风险。** 低于 INT8 的任何位宽都需要以动作误差重新验证。INT4 的失败 [M] 表明，靠位宽换速度的路径风险高。BFP8 目前只有软件精度数据 [M, software]，上板后的精度与时序都待确认。
- **收敛风险。** 运行时可重构的两项技术（融合链对、链分裂）预期收益接近零 [P]。如果继续投入于 GEMM 形状适配，可能得不到时延回报。
- **可比性风险。** Thor 端为 bf16、未给出相对 fp32 的误差，也没有 Thor 端的时延分解；两端的比较口径并不完全对等。此外，GPU 端还有 VLA-Cache [15]、减步数等算法优化可用，FPGA 端若不同步采用，差距可能随时间扩大。
- **平台风险。** 本项目深度依赖 Speedster7t 的 MLP72 级联、2D NoC 和 GDDR6，移植到其他器件需要重做数据流与编译器后端。
- **评估面风险。** 46 帧离线误差是开环指标，还不能代表闭环成功率。VLA 量化文献 [19] 显示，开环误差与闭环成功率之间的关系并不简单。

## 5. 技术路线建议

本节按“预期收益、实现代价、风险、验证方法”四项列出后续方向，并把方向分为三类：

- **结构性改进**：需要改动比特流，重新综合与布线；
- **运行时可重构**：同一比特流内由程序选择；
- **算法侧**：需要与模型方共同验证。

预期收益尽量用简报的 [P] 构成给出**上界**，计算方式为“某项时间占比 × 1.221 s”。这里假设其他项的重叠关系不变。这个假设偏乐观，因此这些上界只用于排序，不是承诺。

### 5.1 结构性改进

**S1　向量通路扩容与重构。** 简报的时延构成把向量通路定位为第一瓶颈（约 50% [P]），INT4 之后约占关键路径的 82% [P]。可选的做法有三种：

- 增加向量节点数或每节点的 lane 数；
- 提高向量域时钟：当前最佳点为 288.9 MHz，低于阵列域的 500 MHz；
- 把 bf16 向量运算改为更窄的定点或块浮点，前提是精度允许。

预期收益：若向量工作整体加速 2 倍，上界约节省 0.31 s [派生：1.221 × 50% × 1/2]；这也会让 INT4、BFP8 等 GEMM 侧的优化重新显现价值。

实现代价：向量节点占用 fabric 逻辑，而 fabric 布线正是当前的约束资源。扩容向量通路很可能要以缩减 GEMM 链为代价。因此，这实际上是一个“矩阵 / 向量算力再配比”的问题，需要借助校准模型做整阵列的设计空间搜索。

风险：两个都有可能发生——扩容后布线失败，或者时钟下降抵消了并行度的收益，fabric-light 链已出现过类似情况。

验证方法：先在校准模型中扫描“链数 × 向量 lane 数 × 时钟”的组合；再对候选点做综合与布线，确认时钟；最后上板测量，并与模型预测做逐项对照。

**S2　把更多非线性算子并入链的结果通路（epilogue 扩展）。** 已上板的 GeGLU / GELU epilogue 带来 −6.1% [M]；RTL 仿真中的 K-split 反量化 epilogue 带来 −6.4% [M, sim]。下一步的候选有三类：

- 反量化 + 残差相加；
- 按 token 求尺度 + 再量化，即把量化尾部整体移入链；
- softmax 的指数与行和，配合 PV 链。

预期收益：每项在个位数百分比量级，但可以叠加。若能消除大部分 int32 结果往返和独立的向量遍历，累计收益有望达到向量工作的一个可观比例。具体数值取决于各算子在向量工作中的占比，而简报没有给出这个细分。

实现代价：每个 epilogue 都要在链的结果通路中增加逻辑，并保证与向量算子逐位一致。对于有归约语义的算子（如 RMSNorm 的平方和、softmax 的行最大值），结果通路需要跨列归约，结构更复杂。

风险：结果通路逻辑增加布线压力与时序压力，可能降低阵列时钟。

验证方法：沿用现有流程——RTL 仿真逐位对比、比特流内开关对比（同一比特流上开 / 关 epilogue），最后整 chunk 上板。

**S3　BFP8 链上板。** 软件模拟中，BFP8 的动作误差（0.70%）优于 INT8（0.97%）[M, software]。

预期收益：主要收益在精度，而不是速度。如果 BFP8 的尺度处理能在链内完成，并借此简化部分量化与反量化的向量工作，也会带来时延收益；这一点需要设计确认。

实现代价：需要重新综合 BFP8 模式的链，并修改编译器的数值模型与期望内存。

风险：块浮点的块大小与共享指数策略对 VLA 的动作误差有影响，软件模拟与硬件实现之间可能存在舍入细节差异；时钟也可能变化。

验证方法：用 46 帧离线误差做首轮验证；如条件允许，再用闭环评测做第二轮。

**S4　片上驻留：前缀 KV 与动作专家的部分权重。** 按 1.2 节的估算：前缀 KV 在 INT8 下约 4.8 MB，BRAM72K 名义总容量约 23 MB [派生]；动作专家 INT8 权重约 0.31 GB [估算]，远超片上容量，只能部分驻留。

预期收益：

- KV 驻留可以消除 10 步 × 18 层对前缀 KV 的片外重读；
- 专家权重若能按层分组驻留，并在步间复用，可以部分削减“串行权重装载”（约 15% [P]，上界约 0.18 s [派生]）。

实现代价：当前的列并行链要求每级 BRAM72K 存放自己那一列的权重。若挪用 BRAM 存放 KV 或常驻权重，会压缩链的分块容量；此外，节点间需要能访问共享的片上存储，而当前架构中节点间只经 GDDR6 通信。

风险：片上存储的再分配可能降低前缀 GEMM 的分块效率，得失需要由模型评估。

验证方法：在校准模型中加入“片上驻留”选项，先确认净收益；再在 PV 链节点上做小规模原型，比较对应阶段的时延。

**S5　布线友好的阵列扩展（fabric-light 推广 + 时钟恢复）。** fabric-light 链让每级逻辑块从 21.2 个降到 2.4 个，并已在硅片上布下 912 个乘法 MLP72 [M]；但时钟降到 310 MHz，整 chunk 为 1.588 s [M]。

预期收益：如果能恢复阵列时钟，并同时扩容向量通路（与 S1 联动），多出来的乘法器才能转化为时延收益。单独扩大 GEMM 阵列的收益上界，受链计算占比约 25% [P] 限制。

实现代价：需要做时序收敛工作，包括定位 fabric-light 设计点的关键路径。

风险：如果 S1 不跟进，扩大 GEMM 阵列的收益会被向量通路吃掉。

验证方法：在相同时钟下比较 fabric-light 与常规链的每级吞吐，再做整 chunk 对比。

**S6　节点间直连与同步开销。** 当前所有同步与中间结果都经 GDDR6 往返。可以考虑在关键的生产者—消费者节点对之间（如 GEMM 链 → 向量节点）加入片上 FIFO 或 NoC 直传，绕开外存。

预期收益：减少 feeder 停顿（约 6% [P]）和 int32 结果的往返。具体收益取决于往返在向量工作中的占比，简报没有细分。

实现代价：会改变“节点仅经 GDDR6 通信”的简洁模型，编译器的同步模型与期望内存模型都要扩展。

风险：直连会增加布线；也会引入新的反压路径，削弱确定性。

验证方法：先在仿真中测量同步与往返时间的实际占比，再决定是否实施。

### 5.2 运行时可重构

这一类方向的共同特征是比特流不变，由编译器在每个 GEMM 或每个阶段选择配置。简报中的两项证据已经显示，在当前瓶颈下这一类的收益很有限：融合链对预计约 0 [P]，链分裂只有 0.02～0.12% [P]。因此，本文建议把运行时可重构定位为**瓶颈转移之后的储备手段**：在 S1、S2 使向量工作显著减少之后，再重新评估。

**R1　融合链对（已在 RTL 仿真中逐位一致）。** 两条链通过链路共享激活行，按 GEMM 选择是否作为一个两倍宽的阵列工作。

- 收益：读流量减少 11～23% [M, sim]；时延收益约为 0 [P]。
- 建议：保留实现，待外存带宽成为瓶颈时（例如 S1 之后）再重新评估。
- 验证：在瓶颈转移后的校准模型中重新计算收益。

**R2　链分裂（32 → 2 × 16）。** 靠静态配置的第二个 feeder，在运行时切换链形态。

- 收益：只比最佳固定形状好 0.02～0.12% [P]。
- 建议：暂不投入上板。

**R3　步间流水与阶段重叠。** 由编译器安排：前缀的最后几层与动作专家的第一步重叠；步 k 的尾部向量工作与步 k+1 的头部 GEMM 重叠。这不需要改硬件，属于调度层面的“运行时”选择。

- 收益：取决于向量工作与 GEMM 的可重叠比例，需要由模型评估。
- 代价：编译器复杂度上升。
- 风险：步间依赖是严格的（Euler 更新），可重叠的只是同一步内不同层之间、以及跨层的独立部分。
- 验证：先在校准模型中评估，再上板。

**R4　按阶段选择精度。** 前提是 S3 或逐层混合精度落地。编译器可以按阶段（SigLIP、前缀、动作专家）或按层，选择 INT8、BFP8 或 INT4 链。当前 INT4 在全部非注意力 GEMM 上不可用 [M]，但这不排除个别不敏感层可以使用 INT4。

- 验证：先做逐层敏感度分析，以动作误差为指标，参考 VLAQuantBench [19] 等工作的方法；再用 46 帧离线误差和闭环评测确认。
- 风险：精度风险，见 4.6 节。

### 5.3 算法侧（需与模型方共同验证）

**A1　减少积分步数。** 流匹配与扩散策略的步数是最直接的时延杠杆；LightDP [40] 等工作都以此为手段。

- 收益：动作专家部分的时间大致与步数成正比。简报没有给出前缀与专家阶段的时间拆分，因此本文不给出数值。建议先由校准模型输出分阶段时延。
- 风险：步数减少可能损失动作质量，需要蒸馏或一致性训练。这超出了硬件团队的控制范围。

**A2　视觉 token 复用与剪枝。** VLA-Cache [15] 在 GPU 上跨帧复用变化小的视觉 token 的 KV，最高带来约 1.7 倍的 CUDA 时延加速。前缀计算约占 85% 的 MAC [估算]，是最大的计算块。

- 在 FPGA 上的代价：编译器需要支持可变的 token 集合，而静态调度的优势正在于形状固定。可以考虑只支持少数几档预编译的 token 数。
- 风险：对静态、确定性调度的冲击较大。

**A3　异步执行与 RTC。** RTC [14] 能使策略对推理延迟更鲁棒。这不减少时延，但放宽了时延约束。它对 FPGA 方案的意义在于：对于动态性不高的任务，1 s 量级的时延也许可以在 RTC 框架下获得可用的闭环表现。这需要闭环实验确认，本文不作判断。

### 5.5 建议补充的测量

以下测量不直接带来加速，但对判断方向和对外比较至关重要。建议优先补齐。

1. **分阶段时延。** 把 SigLIP、前缀、动作专家单步分别计时，以便评估 A1、A2 和 S4 的收益。
2. **板卡功耗与每 chunk 能耗。** 没有这一项，FPGA 方案在“能效”维度上无法与 Thor 或文献比较。
3. **时延分布。** 在多次运行上给出方差与尾时延，把“确定性”从结构推论变为测量结论。
4. **Thor 端的对照细节。** 包括 Thor 端相对 fp32 的动作误差、时延分解，以及功耗模式，使“匹配精度”的比较口径对等。
5. **有效外存带宽。** 测量 GDDR6 经 NoC 的实测有效带宽，用于校准 3.3 节模型中的 $BW_{eff}$。

## 6. 结论

VLA 在 FPGA 上的部署问题，与已被广泛研究的“LLM 解码上 FPGA”相比有本质差别：

- 负载同时包含算力受限的前缀与权重搬运受限的多步动作头；
- 非线性与量化相关的逐元素运算在关键路径上占比高；
- 输出对低比特误差高度敏感。

已发表的 FPGA LLM / Transformer 工作——FlightLLM [22]、DFX [23]、Chen 等 [25]、CHARM [29]、SSR [30]、EdgeLLM [31]——提供了级联阵列、HBM 利用、空间与顺序混合、混合精度等可借鉴的构件。但在本文可检索的范围内，没有工作处理完整 VLA 的单片 FPGA 部署。

本项目以一片 Speedster7t 端到端运行 π0 的整个 chunk，在 W8A8 下达到 1.221 s [M] 与 0.665° 的关节最大误差 [M]，并做到逐拍可核对。在“完整性”和“工程可控性”上，它在文献中具有独特位置。与 Jetson AGX Thor（bf16，125.3 ms [M]）相比，它慢约 9.7 倍 [派生]。按简报自身的校准模型，差距主要来自向量通路与串行权重装载，而不是乘法器数量；乘法器的使用比例则受布线限制。

因此，本文建议后续工作按以下顺序投入：

1. 向量通路的结构性扩容，以及 epilogue 的进一步融合（S1、S2）；
2. BFP8 上板与片上驻留（S3、S4）；
3. 补齐分阶段时延、能耗与时延分布的测量（5.5 节）。

运行时可重构（融合链对、链分裂）在当前瓶颈下预期收益接近零，宜作为瓶颈转移后的储备。算法侧的减步数与 token 复用潜力大，但需要模型方配合，也会与静态调度的确定性属性形成张力。
